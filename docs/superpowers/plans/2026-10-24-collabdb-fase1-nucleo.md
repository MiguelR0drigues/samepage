# SamePage Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A free, remote MCP server where the team's Claude Code agents record and query decisions, views, principles and explorations, with authorship, supersession rules, and a summary injected at the start of every session.

**Architecture:** A TypeScript Hono app on Cloudflare Workers (free, no cold start). Each request builds a stateless `McpServer` bound to the person who owns the token. Business rules and permissions live in a service (`Memory`) that talks to a `Store` interface. There is a single Postgres adapter (Drizzle), backed by Neon in production and PGlite in tests. Export and import use neutral JSON.

**Tech Stack:** Node ≥ 22, TypeScript, Hono, `@modelcontextprotocol/server` (SDK v2), `@modelcontextprotocol/client` (tests only), Zod v4, Drizzle ORM + drizzle-kit, `@neondatabase/serverless` (Worker), `pg` (scripts), `@electric-sql/pglite` (tests), Vitest, Wrangler.

**Spec:** `docs/superpowers/specs/2026-10-24-collabdb-design.md`. This plan covers **Phase 1** only (spec section 8.1). Phase 2 (automatic capture in Claude Code) and Phase 3 (Meet) get their own plans once Phase 1 is running and the items in spec section 11 have been verified.

## Global Constraints

- **Product name: SamePage** (package `samepage`, MCP server name `samepage`, env vars `SAMEPAGE_URL`/`SAMEPAGE_TOKEN`). The repo folder stays `CollabDB`.
- **Everything in English:** code, identifiers, enum values, MCP tool names and parameters, error messages, server instructions, summary text, READMEs and commit messages.
- Zero monetary cost: free tiers only. **No Vercel Hobby plan.**
- The MCP server **never calls AI models**. It only reads and writes data.
- Short responses to save agent context:
  - search returns 5 entries by default, 20 at most;
  - each entry's content is truncated to 500 characters in responses.
- The session-start summary is at most **2000 characters** (~500 tokens).
- Permissions live in the `Memory` service, never in row-level security.
- Only files under `src/storage/postgres/` and `scripts/` import Drizzle or database drivers. Everything else talks to `Store`.
- Tokens are 32 random bytes in hex. Only their SHA-256 is stored.
- A decision's verdict (`content`) is never edited. It changes only through `supersede_decision` or `propose_revision`.
- The session-start hook must never break a session: on any error it exits 0 with no output.

## Review Focus

1. **Unknown authors.** The agent may invent or misspell a name in `authors`. It must get a clear error listing the valid ids, never an orphan entry. Test in Task 3.
2. **Server down, missing token, or slow response in the hook.** The Claude Code session opens normally, with no summary and no visible error. Test in Task 7.
3. **Deleted entries.** They never appear in search, listings, or the principles/decisions sections of the summary. They appear as "removed" in other people's what's-new list. Tests in Tasks 2 and 4.
4. **Proposals in invalid states.** Accepting your own proposal, accepting an already closed proposal, or proposing a revision of a decision that already has an open proposal: clear error, no data changed. Test in Task 3.
5. **Two near-simultaneous supersessions of the same decision.** Only one may win; the other gets "This decision is no longer active." Guaranteed by a transaction that re-checks the status. Test in Task 3.

### Task 3: `Memory` service (rules and permissions)

**Files:**
- Create: `src/service/memory.ts`
- Test: `tests/service/memory.test.ts`

**Interfaces:**
- Consumes: `Store`, types.
- Produces:

```ts
export class MemoryError extends Error {}
export interface RecordInput {
  type: Exclude<EntryType, 'proposal'>; title: string; content: string; area: string;
  authors?: string[]; question?: string; positions?: Position[]; consensus?: Consensus;
  consensusReason?: string; sourceKind?: SourceKind; sourceRef?: string;
}
export class Memory {
  constructor(store: Store);
  record(actor: Person, input: RecordInput): Promise<Entry>;
  correctText(actor: Person, id: string, patch: Partial<Pick<Entry, 'title' | 'question' | 'positions' | 'consensusReason' | 'content'>>): Promise<Entry>;
  remove(actor: Person, id: string): Promise<void>;
  supersede(actor: Person, oldId: string, input: RecordInput): Promise<{ entry: Entry; outcome: 'superseded' | 'proposal' }>;
  proposeRevision(actor: Person, decisionId: string, input: { title: string; content: string; justification: string }): Promise<Entry>;
  acceptProposal(actor: Person, id: string): Promise<Entry>;   // returns the new decision
  rejectProposal(actor: Person, id: string, note?: string): Promise<Entry>;
}
```

**Rules (spec sections 6.1 and 6.7):**
- `record`:
  - `authors` defaults to `[actor.id]`. If the actor is a system person (`isSystem`), `authors` is required and must not include it.
  - Every author must exist and must not be a system person. Otherwise `MemoryError` with the message `Unknown authors: X. Valid ids: a, b, c`.
  - Status is `active`, and `sourceKind` defaults to `explicit`.
- **Team decision:** `authors.length >= 2 || sourceKind === 'meet'`.
- `correctText`: only authors may correct. On a `decision`, `content` in the patch → `MemoryError('A decision verdict cannot be edited: use supersede_decision or propose_revision.')`.
- `remove`: only authors. Soft delete (`deletedAt`, `deletedBy`).
- `supersede`, all inside `store.transaction`, re-reading the old decision there:
  - the old entry must be a `decision` with status `active`. Otherwise `MemoryError('This decision is no longer active.')`;
  - **supersedes directly** if the new one is a team decision, or if `old.authors` is exactly `[actor.id]`. The new entry is an `active` `decision` with `supersedesId = old.id`, and the old one becomes `superseded`;
  - otherwise it creates a **proposal**: `type 'proposal'`, `status 'open'`, `targetId = old.id`, `authors [actor.id]`. The old one becomes `under_review`.
- `proposeRevision`:
  - the decision must be `active`. If it is `under_review`, `MemoryError('This decision already has an open proposal.')`;
  - creates the proposal as above, with `content` = suggestion, the justification appended after `\n\nJustification: `, and `resolutionNote` = null.
- `acceptProposal` and `rejectProposal`, in a transaction:
  - the proposal must be `open`. Otherwise `MemoryError('This proposal is already closed.')`;
  - the actor must not be in `proposal.authors`: `MemoryError('You cannot close your own proposal.')`;
  - **accept:** the proposal becomes `type 'decision'`, `status 'active'`, `supersedesId = targetId`, `authors = [...authors, actor.id]`. The target becomes `superseded`;
  - **reject:** the proposal becomes `rejected`, with `resolutionNote = note ?? null`. The target goes back to `active`.
- A system actor cannot call `remove`, `correctText`, `acceptProposal` or `rejectProposal`.

- [ ] **Step 1: Write the failing tests.** People `miguel`, `joao` and the system person `meet`. Tests:
  - `record uses the actor as the default author`.
  - `record rejects unknown authors with the list of valid ids`: expects `MemoryError`, with the message containing `Unknown authors: ana` and `joao, miguel`.
  - `record by the system requires authors`.
  - `only authors can delete` and `a deleted entry disappears from listEntries`.
  - `a decision verdict cannot be edited`; `an author can correct the title`.
  - `a team decision supersedes directly`: old with authors `[miguel, joao]`, new with `authors [miguel, joao]` → `outcome 'superseded'`, old is `superseded`, new has `supersedesId` equal to the old id.
  - `one person against a team decision creates a proposal`: `outcome 'proposal'`, old is `under_review`.
  - `a sole owner supersedes their own decision directly`.
  - `a meet decision counts as a team decision`.
  - `another person accepts a proposal and it supersedes the original`: final authors are `[miguel, joao]`.
  - `rejecting restores the original to active and stores the reason`.
  - `cannot accept your own proposal`; `cannot accept an already closed proposal`; `cannot propose a revision while one is open`.
  - `concurrent supersessions: only one wins`: `Promise.allSettled` of two team `supersede` calls on the same decision → exactly one `fulfilled` and one `rejected` with `This decision is no longer active.`. If PGlite serializes transactions, the test still holds because the second one re-reads the status.
